# 错误码参考

API 调用出错时会返回 HTTP 状态码和错误信息。以下是常见错误及解决方法。

---

## 400 Bad Request — 请求体格式错误

请求体不是合法的 JSON 时，平台返回 400：

```json
{
  "error": {
    "code": "",
    "message": "无效的请求，invalid JSON request body (request id: ...)",
    "type": "new_api_error"
  }
}
```

**解决**: 检查请求体是否为合法 JSON，确认没有多余的逗号、缺少引号等语法错误。

---

## 401 Unauthorized — 认证失败

```json
{
  "error": {
    "code": "",
    "message": "Invalid token (request id: ...)",
    "type": "new_api_error"
  }
}
```

**排查**:
1. 确认 API Key 格式正确（以 `sk-` 开头）
2. 确认 API Key 未过期、未禁用
3. 确认 `Authorization` 头格式正确：`Bearer sk-xxxxxxxx`
4. 如果使用 Claude 格式，确认用 `x-api-key` 而非 `Authorization`

---

## 402 Payment Required — 余额不足

```json
{
  "error": {
    "message": "Insufficient balance",
    "type": "billing_error",
    "code": "insufficient_quota"
  }
}
```

**解决**: 充值后重试。进入控制台 → 钱包 → 充值。

---

## 403 Forbidden — 权限不足

```json
{
  "error": {
    "message": "Model not allowed for this token",
    "type": "permission_error",
    "code": "model_not_allowed"
  }
}
```

**排查**:
1. 检查令牌是否设置了模型限制
2. 检查令牌是否设置了 IP 白名单
3. 确认账户状态正常

---

## 503 — 模型不存在或渠道暂不可用

调用不存在的模型，或对应模型的上游渠道暂时不可用时，平台会返回 503：

```json
{
  "error": {
    "code": "model_not_found",
    "message": "分组 default 下模型 xxx 无可用渠道（distributor） (request id: ...)",
    "type": "new_api_error"
  }
}
```

**解决**:
1. 检查模型名称拼写。当前可用模型（10 个）：
   - `deepseek-v4-flash`、`deepseek-v4-pro`
   - `kimi-k2.7-code`、`kimi/kimi-k3`
   - `qwen3.7-flash`、`qwen3.7-plus`、`qwen3.7-max`
   - `glm-5.2`
   - `MiniMax-M2.5`、`MiniMax/MiniMax-M3`
2. 若模型名正确，说明上游渠道暂时不可用，换一个模型重试，或等待几分钟后重试。

---

## 429 Too Many Requests — 请求过于频繁

```json
{
  "error": {
    "message": "Rate limit exceeded",
    "type": "rate_limit_error",
    "code": "rate_limit_exceeded"
  }
}
```

**解决**: 降低请求频率，或添加重试逻辑：

```python
import time
from openai import OpenAI, RateLimitError

client = OpenAI(api_key="sk-xxx", base_url="https://www.aytdai.com/v1")

def chat_with_retry(messages, max_retries=3):
    for attempt in range(max_retries):
        try:
            return client.chat.completions.create(
                model="deepseek-v4-flash",
                messages=messages
            )
        except RateLimitError:
            time.sleep(2 ** attempt)
    raise Exception("Max retries exceeded")
```

## 500 Internal Server Error — 服务器内部错误

**可能原因**:
- 上游 AI 服务临时故障
- 请求缺少必要参数（如 `messages` 字段），此时返回 `code: "invalid_request"`：

```json
{
  "error": {
    "message": "field messages is required (request id: ...)",
    "type": "new_api_error",
    "param": "",
    "code": "invalid_request"
  }
}
```

**解决**:
- 若为参数错误：检查请求体是否包含所有必填字段（`model`、`messages`）
- 若为上游故障：等待 1-2 分钟重试。如持续出现请联系我们。

---

## 502 — 网关错误

**可能原因**: 网关无法连接到上游 AI 服务

**解决**: 等待几分钟后重试。如持续出现请联系我们。

---

## 504 Gateway Timeout — 请求超时

**可能原因**: 请求处理时间过长

**解决**:
1. 减少 `max_tokens` 参数
2. 使用流式输出 `"stream": true`

---

## 上游错误

部分错误来自上游 AI 服务商：

| 错误码 | 说明 |
|--------|------|
| `context_length_exceeded` | 输入超出模型上下文长度 |
| `invalid_request_error` | 请求格式不符合规范 |
| `content_policy_violation` | 内容违反使用政策 |
| `model_overloaded` | 模型过载 |

---

## 调试技巧

1. **查看请求日志** — 控制台日志页面记录每次调用详情
2. **用 curl 测试** — 排除客户端问题：

```bash
curl -v https://www.aytdai.com/v1/chat/completions \
  -H "Authorization: Bearer sk-xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"model":"deepseek-v4-flash","messages":[{"role":"user","content":"hi"}]}'
```

3. **检查响应头** — `X-Oneapi-Request-Id` 可用于定位问题（错误信息末尾也会附带 request id）
